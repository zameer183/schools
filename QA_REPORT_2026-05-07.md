## 3. What is NOT Working / Broken ❌

### 3.1 Forgot Password page is a FAKE STUB — HIGH severity
**File:** `app/(auth)/forgot-password/page.tsx`
**Problem:** Lines 14–17 simply do:
```ts
await new Promise((r) => setTimeout(r, 1000));
setSent(true);
```
There is no API call, no token generation, no email send. The user enters an email, sees "Check Your Inbox", but nothing actually happens.
**Fix:** Build `POST /api/auth/forgot-password` (issue token, store in DB, email or whatsapp the link) + a `/reset-password?token=...` page that calls `POST /api/auth/reset-password`.

### 3.2 Teacher / Student / Parent logins fail in current DB — HIGH severity
Per the prior `QA_TEACHER_STUDENT_A_TO_Z_2026-05-02.md`:
- `teacher@stitchhms.com` → `401 user_not_found`
- `student@stitchhms.com` → `401 user_not_found`
The seed script defines these accounts, so the live DB has drifted from seed. Full role-based runtime QA is blocked until these are restored.
**Fix:** `npm run prisma:seed` against the current DB, or insert TEACHER/STUDENT/PARENT users manually.

### 3.3 WhatsApp dispatch worker fails — MEDIUM severity (env config)
**Evidence:** `qa-dev.err.log`, `qa-template-dev.err.log`:
```
error: 'Missing required env var: WHATSAPP_CLOUD_PHONE_NUMBER_ID'
error: 'QA provider failure'
error: 'Provider template failure'
```
`src/lib/whatsapp-provider.ts` requires `WHATSAPP_CLOUD_PHONE_NUMBER_ID`, `WHATSAPP_CLOUD_ACCESS_TOKEN`, optional `WHATSAPP_CLOUD_API_VERSION`. None are set in `.env` (only `DATABASE_URL`, `JWT_SECRET`, `NEXT_PUBLIC_*` vars).
**Impact:** Campaigns/automation can build queues but real WhatsApp sends will always fail. wa.me deeplinks (used in Finance UI) still work because they don't need API.
**Fix:** Add Meta WhatsApp Cloud API credentials to `.env`, OR skip campaigns module if not used.

### 3.4 Dev script crashes on Windows port-free — LOW severity
**File:** `scripts/dev.mjs` line 38
**Evidence:** `dev_verify3.err.log`:
```
ReferenceError: ownerPid is not defined
    at killPortListenerWindows (scripts/dev.mjs:38:24)
```
The PowerShell-emitting code references `ownerPid` outside scope. When port 5000 is held by a stale process, the dev script crashes instead of freeing the port. Workaround: kill the process manually.
**Fix:** Define `ownerPid` and `parentPid` from the lookup result before emitting `Write-Output`.

### 3.5 Orphan / dead code: `app/admin/reports-page.tsx` — LOW severity
- 45 KB file, **not imported anywhere** (real reports UI is `app/admin/reports/page.tsx`).
- Contains a fake "Generate Report" handler (`setTimeout(1800)` then toast — no real call).
- Just clutter; safe to delete.
**Fix:** `git rm app/admin/reports-page.tsx`.

### 3.6 Stray empty directory `app/\(auth\)/login/` — LOW severity
- A literal `\(auth\)` folder (with backslashes in the name) was created by accident, contains an empty `login/` subdir.
- Real route group is `app/(auth)/`. The stray dir doesn't break Next.js but is clutter.
**Fix:** Delete `"app/\(auth\)"` (in PowerShell: `Remove-Item -Recurse 'app/\(auth\)'`).

### 3.7 Mobile attendance heatmap not visible — LOW severity (cosmetic)
Per QA artifact `phase2-p1-postfix`:
```json
"attendanceVisibility": { "passHeatmap": true, "detail": { "heatmapVisible": false } }
```
Summary tiles render at 375px, but the heatmap visualization isn't shown on mobile. Marked `pass` because of viewport, but worth confirming intent.

### 3.8 Many leftover dev log files in repo root — LOW severity (housekeeping)
20+ `dev*.err.log` / `dev*.out.log` files at the repo root. They are not in `.gitignore` and clutter the project.
**Fix:** `git rm dev*.log qa*.log dev_*.log` and add `*.log` to `.gitignore`.

### 3.9 Middleware only protects `/api/admin/*`
By design (per `replit.md`), other roles are protected by server-side `requireAuth()` in pages. This is correct, but worth re-verifying redirect behavior once teacher/student/parent accounts are restored (item 3.2).
